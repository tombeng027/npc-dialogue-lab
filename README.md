# npc-dialogue-lab

An NPC generator module that allows you to create custom NPCs by defining specific metrics, converse with them dynamically, and generate contextual quests based on active world events.

NPC Dialogue Lab is a module for creating and interacting with dynamic Non-Player Characters (NPCs).

- **Custom Generation:** Define specific NPC traits, stats, and behavior metrics.
- **Interactive Dialogue:** Engage in real-time conversations with generated NPCs.
- **Context-Aware Quests:** Automatically generate relevant quests based on active player actions and world state updates.

## Requirements

- Python 3.10 or newer (developed on 3.14)
- One LLM provider:
  - **Ollama (default):** [install Ollama](https://ollama.com) and pull a model, e.g. `ollama pull llama3.1:8b`
  - **OpenAI (optional):** an API key

Python dependencies are listed in [requirements.txt](requirements.txt): FastAPI, Uvicorn, Pydantic, the Ollama client and the OpenAI client.

## Setup

```powershell
git clone https://github.com/tombeng027/npc-dialogue-lab.git
cd npc-dialogue-lab
python -m venv .venv
.\.venv\Scripts\Activate.ps1        # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

## Run

```powershell
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Open <http://127.0.0.1:8000/> for the workbench UI. Interactive API docs are at <http://127.0.0.1:8000/docs>.

A quick command-line demo is also available: `python demo.py` (needs the configured LLM provider).

## Configuration

Set these environment variables before starting the server.

| Variable | Default | Purpose |
|---|---|---|
| `NPC_LLM_PROVIDER` | `ollama` | `ollama` or `openai` |
| `OLLAMA_MODEL` | `llama3.1:8b` | Ollama model name |
| `OLLAMA_HOST` | `http://localhost:11434` | Ollama server address |
| `OPENAI_API_KEY` | none | Required when the provider is `openai` |
| `OPENAI_MODEL` | `gpt-4o-mini` | OpenAI model name |

Example for OpenAI:

```powershell
$env:NPC_LLM_PROVIDER = "openai"
$env:OPENAI_API_KEY = "<your key>"
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

## How it works

- Each NPC has a profile (name, job, attitude, likes/dislikes, backstory, quest lines).
- Quests are only offered from the NPC's own quest lines. An NPC with none makes small talk, gossips about current events, or brushes the player off depending on its personality.
- Quest steps are generated by the model but validated against the world's actions and items, so they can always be completed.

### Main endpoints

| Method | Path | Purpose |
|---|---|---|
| GET/POST | `/npcs` | List or create NPCs |
| GET/PUT/DELETE | `/npcs/{npc_id}` | View, edit or delete an NPC |
| POST | `/npcs/{npc_id}/chat` | Talk to an NPC |
| GET | `/npcs/{npc_id}/conversation` | Conversation history |
| GET/POST | `/world`, `/world/locations` | World map and locations |
| POST | `/world/actions/{action_id}/perform` | Perform a world action |
| GET | `/inventory`, `/wallet` | Player inventory and coins |

## Deployment notes

- The default Ollama provider needs a model running on the same machine or network. For a hosted deployment, use `NPC_LLM_PROVIDER=openai`.
- State (NPCs, conversations, inventory, wallet) is held in memory and resets whenever the server restarts.
- There is no authentication and the world is shared by all visitors, so it suits demos and local use. Add authentication and persistent storage before exposing it publicly.
- Run behind a production server, for example `uvicorn main:app --host 0.0.0.0 --port 8000`, and keep API keys in environment variables, never in the repo.
